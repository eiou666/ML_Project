## 测量与瓶颈

硬件为 i5-12600KF（10 核、16 逻辑处理器）和 RTX 3060 Ti。旧的确定性训练直接在主进程逐张执行 CPU 图像增强，绕过了训练 DataLoader 的多进程取数。即使配置中 num_workers=2、pin_memory=true，原确定性取批路径也没有使用相应的数据预取和锁页内存功能。

首次隔离试跑测得每步约 180 ms，其中准备数据约 153 ms（85%）。随后使用同一脚本、同一真实 Fashion-MNIST 配置和同样 85 步（排除前 5 步预热）作串行与并行比较：

## 实现与复现

- 新增 src/prefetch.py：一个任务准备一个完整训练步，包括标注批次与无标签双视图，多个独立 CPU 进程提前准备后续步骤，GPU 同时训练当前步骤。
- 保持原有按 seed 和 global_step 的抽样顺序；标注和无标签增强在同一个任务中按原顺序执行。
- 将增强后的 Python、NumPy、PyTorch CPU 随机状态传回主进程，保留原有 CUDA 随机种子设置；worker 不初始化 CUDA。
- 使用有序 DataLoader、独立 loader 随机生成器和锁页内存；不改变模型、标签划分、批量、增强分布、学习率、AMP 或总训练步数。
- 后台入口 scripts/run_local.py 默认设置 ML_PREFETCH_WORKERS=4；可在启动前设置为 0 回退串行。直接运行 src.run 时默认仍为 0，需显式设置此环境变量以启用预取。
- 预取进程数属于执行方式，不改变研究配置哈希。新的 metrics.json 在 execution 字段记录 prefetch_workers 和 torch_threads。

19 项测试全部通过（14.54 秒）。新增测试验证跨 epoch 的批次和随机状态一致，并在正式批量 64/192、CUDA AMP、无监督损失实际启用的情况下，验证从串行检查点切换到 4 进程预取后，训练模型与 EMA 参数均逐元素一致。
